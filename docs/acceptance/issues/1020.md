## What is wrong

`track.set_mute`, `track.set_solo` and `track.set_arm` route `[.accessibility, .mcu, .cgEvent]` (`RoutingTable.swift`). When the Accessibility channel refuses, the router falls back to MCU, and `MCUChannel.executeStripButton` sends the strip button like this:

- `enabled: true` sends a press. Logic's Mute, Solo and Rec buttons toggle on the press. So on a track that is already muted, `set_mute enabled:true` unmutes it.
- `enabled: false` sends `[0x90, note, 0x00]` and nothing else. That is a release with no press, and Logic does nothing with it. So the fallback can never clear a mute, solo or arm.

Neither branch reads the current state first. The reply is State B `readback_unavailable` in both cases, so it does not claim success. But the `true` branch can write the opposite of what the caller asked for.

## How this was found

I found it by reading the code at `b992857e` while fixing the missing button release (#862, where the release fix lands). The behaviour above follows from how Logic handles MCU buttons, measured for the bank buttons on 2026-09-26. I have not reproduced it live for mute, solo or arm.

## What would close it

A set on MCU either:
- reads the current state first, and presses only when it differs, then confirms the change by readback; or
- refuses, so the router moves on to the next channel.

A toggle must not be presented as a set.

Refs #862 for the release fix that exposed it.
