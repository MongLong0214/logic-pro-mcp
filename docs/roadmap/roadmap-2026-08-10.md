## Wave 1 — close the trust kernel (#373, #284)

#373 is the evidence engine and #284 is the gate that consumes it, so they run together in that order.

#373 asks for real per-operation evidence at three depths (A:20 → B:51 → C-live:35). The live method
this needs already exists in working form: drive the release artifact through the real transport,
capture Logic's own window surface, hash decoded pixels, require a settled frame, and bind the capture
to the object the product acted on by name rather than by screen position. Wave 1 turns that from a
set of scratch scripts into a repeatable harness and runs it across the operation registry.

#284 then becomes mechanical: the gate is "same release artifact, real Logic, evidence per operation",
and #373 produces exactly that. Until #284 closes, nothing below may be called GA.

## Wave 2 — runtime resilience (#290, #289)

**#290 (ADR-007, AX Selector Atlas and UI Drift Detector) comes before every domain epic.** Every
capability below addresses Logic through AX selectors, and this session produced repeated evidence
that ad-hoc selectors are the main source of wrong-target work: an occupied insert slot is a different
element kind from an empty one; the Inspector and the mixer expose the same `AXLayoutArea(Mixer)` and
are separated only by the enclosing group's description; a track header's children include Mute
directly after a splitter and a disclosure triangle. An atlas plus a drift detector turns each of
those from a discovery into a fixture.

#289 (ADR-006 versioned cache) follows; the flag and envelope fields already exist, so this is
completion rather than green-field.

The remaining #475 item lands here: the Go-to-Position classifier should require a dialog role and an
exact title rather than a substring of any window title.

- **#291 ADR-008 Verified Mixer Routing Graph.** Measured obstacle to plan around: a routing button's

## Wave 5 — MIDI and piano roll (#302, #303)

#302 depends on #293's provider decision. Known obstacle: the Event List exposes position and length
as four-segment `AXSlider` groups, no AX path descends from a region row into note events, and a row's
only action is a custom Delete. #303 (piano-roll transforms) depends on #302 for identity.

## Wave 6 — advanced control (#304, #305, #306)

#304 (Smart Tempo) is implementation. **#305 (Flex Pitch) and #306 (third-party host parameters) are
the two most likely to be wall-bound**: the AU parameter view has been observed AX-opaque. Each starts
with a measurement step, and if the surface is genuinely unreachable the issue closes as a scope
decision with the measurement attached — not as a silent deferral.

## Wave 7 — product issues with expected scope decisions (#369, #448)

Both are likely to need a decision rather than an implementation, and both must be measured first:

- **#369 per-track stem export.** The export panel is AX-drivable, but its per-track filename fields
  report `settable=true` and do not accept writes. If that holds, per-track stems cannot be driven
  from this surface and the issue closes with the measurement.
- **#448 verified track-layout readback, colour and reorder.** Colour is settable but not readable —
  97 press-only swatches, no colour attribute anywhere in an 859-node sweep — so a *verified* colour
  operation cannot exist without a readback. Reorder is drag-only: `Track ▸ Sort Tracks by` offers
  seven global criteria, `Edit ▸ Move` is region movement, and the 24-item track context menu has no
  move. The layout **readback** half is deliverable; the colour and reorder halves need an explicit
  decision on what "verified" means for a write nothing can read back.

## Rules this roadmap keeps

1. **Order is not negotiable where #308 states it.** The trust kernel precedes domain work; ADR-001
   precedes any GA claim.
2. **Every implementation is proven live** against the release artifact, screen-recorded, with Logic's
   own window surface captured and the target bound by identity rather than screen position.
3. **Every guard is mutation-tested.** A check that has not been observed to fail is not evidence, and
   a control that cannot see what it forbids is a finding in itself.
4. **A wall is measured, then decided.** An issue that cannot be delivered as a verified operation
   closes with the measurement that proves it, never as a silent deferral.
5. **Blocked-on-environment stays open.** #440's finding E is the current example.
