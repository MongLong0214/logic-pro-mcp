## Where the order comes from

The canonical dependency chain is not invented here. It is stated in issue #308 (ADR-001~018
Implementation Work Guide):

```
ADR-002 Stable Target -> ADR-003 Operation Registry -> ADR-005 Trace
      -> ADR-004 Mutation Saga -> ADR-001 Same-Artifact Live Qualification
```

Four of those five are closed: #285 (002), #286 (003), #287 (004), #288 (005). **ADR-001 (#284) is
the one open link.** Rule 4 of the guide — "a capability not verified in the real Logic environment
with the same release artifact must not be claimed as GA" — makes it a *claim* gate, not a build
prerequisite: it is what every finished capability must pass through before it can be called GA, so it
sits at the end (Wave 7) and no wave before it may claim GA.

### What this changes about the plan

**Rule 3 needs a companion.** "Every guard is mutation-tested" held, and it is what caught most of
these. What it does not cover is a guard aimed at the wrong thing: #565's suite passed because its
fixture built a table shape Logic never presents, and #578's scenario failed steps the project had
formally declared could not pass. Both were green, both were mutation-testable, neither measured the
product. The addition:

> **A check states what it is aimed at, and that aim is checked against the running system —**
> the fixture against the live tree, the expectation against the operation's own qualification.

**A gate for #575's class was attempted and withdrawn.** The missing direction is routing → caller;
nothing walks it. A static census over `Sources/` cannot: this codebase computes operation strings
(`operation: "plugin.\(command)"`), so no textual predicate can see those callers. An execution
census has the mirror problem — driving every handler with empty params reports un-driveable as
unreachable. Recorded on #575 with all three predicates tried, so the next attempt starts after them
rather than at them.

**Measurement grows the fixture.** Repeated live runs pushed the scratch project past the arrange
viewport, at which point `record_sequence` cannot read back its own region — and two published
characterisations of #572 were wrong because they were measured there. Any live measurement of a
create-shaped operation resets the project first and takes three samples before a rule is written
down.

## Wave 1 — MIDI readback, the one thing nothing else can substitute (#302, #293, #303)

A write is only verified if something independent can read it back, so the readback provider precedes
every verified-write surface rather than following them.

#302 builds the independent readback and verifies `midi.import_file` and `tracks.record_sequence`
against the release artifact. Known obstacle: the Event List exposes position and length as
four-segment `AXSlider` groups, no AX path descends from a region row into note events, and a row's
only action is a custom Delete.

#293 selects and hardens the provider — duplicate-preserving canonical comparison, PPQ normalisation,
and negatives for stale, wrong-region and mismatched reads. #303 (piano-roll transforms) then takes
its expected notes from that provider and never from the write plan it is trying to check.

## Wave 2 — runtime resilience (#290, #289)

**#290 (AX Selector Atlas and UI Drift Detector) comes before every domain epic.** Every capability
below addresses Logic through AX selectors, and live work produced repeated evidence that ad-hoc
selectors are the main source of wrong-target behaviour: an occupied insert slot is a different element
kind from an empty one; the Inspector and the mixer expose the same `AXLayoutArea(Mixer)` and are
separated only by the enclosing group's description; a track header's children place Mute directly
after a splitter and a disclosure triangle. An atlas plus a drift detector that fails closed on an
unrecognised tree turns each of those from a discovery into a fixture.

#289 (versioned cache) follows; the flag and envelope fields already exist, so this is completion
rather than green-field.

#489 closed in Wave 0: `logic://project/info` now carries a fresh exact project identity with its
source and age, so a client can bind a write to an exact project. The Go-to-Position item that was
parked here closed with it.

#304 (Smart Tempo) is implementation. **#306 (third-party host parameters) and #305 (Flex Pitch) are

## Wave 6 — issues with expected scope decisions (#448, #369)

Both are likely to need a decision rather than an implementation, and both must be measured first.
They are resolved before the trust kernel so the completion count is honest at the gate rather than
after it.

- **#448 verified track-layout readback, colour and reorder.** Colour is settable but not readable —
  97 press-only swatches, no colour attribute anywhere in an 859-node sweep — so a *verified* colour
  operation cannot exist without a readback. Reorder is drag-only: `Track ▸ Sort Tracks by` offers
  seven global criteria, `Edit ▸ Move` is region movement, and the 24-item track context menu has no
  move. The layout **readback** half is deliverable; the colour and reorder halves need an explicit
  decision on what "verified" means for a write nothing can read back.
- **#369 per-track stem export.** The export panel is AX-drivable, but its per-track filename fields
  report `settable=true` and do not accept writes. If that holds, per-track stems cannot be driven
  from this surface and the issue closes with the measurement.

## Wave 7 — close the trust kernel (#373, #284)

#373 is the evidence engine and #284 is the gate that consumes it, so they run together in that order.

#373 asks for real per-operation evidence at three depths (A:20 → B:51 → C-live:35). The live method
this needs already exists in working form: drive the release artifact through the real transport,
capture Logic's own window surface, hash decoded pixels, require a settled frame, and bind the capture
to the object the product acted on by identity rather than by screen position. Wave 7 turns that from
a set of scratch scripts into a repeatable harness and runs it across the operation registry.

#284 then becomes mechanical: the gate is "same release artifact, real Logic, evidence per operation",
and #373 produces exactly that. Until #284 closes, nothing in this program may be called GA.

## Rules this roadmap keeps

1. **Order is not negotiable where #308 states it.** ADR-001 (#284) precedes any GA claim, and the
   independent MIDI readback precedes every verified-write surface, because a write nothing can read
   back is not a verified write.
2. **Every implementation is proven live** against the release artifact, screen-recorded, with Logic's
   own window surface captured and the target bound by identity rather than screen position.
3. **Every guard is mutation-tested.** A check that has not been observed to fail is not evidence, and
   a control that cannot see what it forbids is a finding in itself.
4. **A wall is measured, then decided.** An issue that cannot be delivered as a verified operation
   closes with the measurement that proves it, never as a silent deferral.
5. **Blocked-on-environment stays open.** #440's finding E is the current example.
